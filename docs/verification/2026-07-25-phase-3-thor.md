## What Phase 3 delivers

The designed bottom-screen gameplay HUD replacing the Phase 2 debug readout:
vitals bar (hearts, magic, rupees, day/clock/countdown), full-bleed Termina
map with area label, MAP·ITEMS·MASKS nav (ITEMS/MASKS inert until Phase 5),
idle plate on title/file-select, diagnostic plates for bridge faults.

## Environment events that shaped this session

1. **The wheelhouse VM migration had dropped the build toolchain** (docker,
   adb, the build image are host state, not repo state). Rebuilt locally from
   `docker/Dockerfile.android`; the durable fix is `tools/bootstrap-build-host.sh`
   plus HANDOFF §9's warning.
2. **The debug signing keystore did not survive the migration** (it lived in
   the old host's `termina-ds-android-home` Docker volume). The Phase 2 build
   on the Thor was signed with the lost key → `INSTALL_FAILED_UPDATE_INCOMPATIBLE`
   → one-time uninstall/reinstall. All game data (`mm.o2r`, `MM.z64`, saves,
   mods, config) lives in `/sdcard/2S2H` shared storage and survived; saves
   were additionally backed up to the server first. **The active debug
   keystore is now the one in this VM's `termina-ds-android-home` volume —
   losing it repeats the uninstall dance. A real release keystore
   (`tools/make-keystore.sh`) is the durable fix, still pending.**
3. The device also needed a fresh wireless-adb pairing (old host's adb keys
   gone) and the app's legacy-data import (`offerLegacy2S2HImport`) ran on
   first boot because the fresh install defaulted to the rebranded
   `/sdcard/TerminaDS` root.

## Amendments driven by hardware verification

Every one of these was invisible to two per-task Codex reviews, an xhigh
whole-branch review, and 81 JVM tests — they only fell out of eyes (and a
camera) on the physical panel:

- **`7df18f8d4` — 1.5× legibility pass.** The handoff's px values were
  authored on a desktop monitor; at the panel's ~320 dpi they render ~3×
  smaller physically than designed. All type and reading-critical glyphs
  scale by `LEGIBILITY = 1.5`; structural geometry unchanged.
- **`eb5f8d0c3` — lay out under the second-screen navbar.** Android reserves
  a 55 px navbar strip on the presentation display; an unfocusable window
  cannot hide the bar, so the window claims the full frame via
  `FLAG_LAYOUT_NO_LIMITS | FLAG_LAYOUT_IN_SCREEN` (measured result:
  frame `[0,0][1240,1080]`).
- **`8edc0ddcd` — nav underline pinned to label width.** The real cause of
  the user-reported "purple line": `fillMaxWidth()` inside a wrap-content
  Column expands to max constraints, so the MAP tab consumed the whole nav
  row, pushed ITEMS/MASKS off-screen, and drew its underline edge-to-edge.
  Caught only by the user photographing the FLAG_SECURE panel.
- **`320027985` — dismiss on background + quarter-heart pie.** The Phase 1
  "Presentation stays up when backgrounded" decision was wrong in practice
  (it sat on top of other apps' second-screen content); the Presentation now
  dismisses at activity stop and returns on resume — the stall chip covers
  in-game stalls only. Hearts quantize to quarters and drain as a pie wedge,
  matching the game's visual language. Also removed the dead
  `insetsController.hide()` block from the first (misdiagnosed) strip fix.
- **`32abec15a` — hearts drain counterclockwise**, per user correction on
  device.

## Process lessons

- **On a FLAG_SECURE panel, the user's camera is ground truth.** The nav bug
  survived every review because the dimmed tabs were invisible in person and
  the full-width line read as intentional; one photo identified it in
  seconds. Ask for the photo *first* when a visual report and the code's
  intent disagree.
- **A real measurement can still be the wrong diagnosis.** The 55 px navbar
  strip was genuine (and worth fixing) but was not what the user was
  reporting; two fix cycles went to the wrong target because the diagnosis
  pattern-matched to available instrumentation instead of the observation.
