## Bug found and fixed during verification

The placeholder's refresh-rate readout showed 60 Hz while the secondary display
was actually at 120 Hz. Two causes, both fixed (commit `540f90f`) and re-verified
on-device (reads 120 Hz; follows a live 60↔120 toggle without an app restart):

1. `Display.getRefreshRate()` reports an unreliable value for secondary /
   presentation displays — switched to the active `Display.Mode`'s rate.
2. `refresh()` no-op'd whenever the same display was still showing, so a live
   mode change never rebuilt the Presentation — now compares the full
   `DisplayInfo` (incl. rate) and re-shows on any change.

## Assessment

The Phase 1 foundation is verified on real hardware: the second screen is
discovered, a `Presentation` hosts the Compose UI on the bottom panel, the JNI
seam is live, the game keeps input focus, and the app survives the ordinary
lifecycle. The architecture decision (`Presentation` + Compose, spec §7) holds on
the Thor.
